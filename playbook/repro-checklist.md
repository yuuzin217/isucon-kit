# 再現性チェック用チェックリスト

ISUCON では競技後に環境を再起動（または再構築）して、スコアが再現するか確認されることがある。手作業で直しただけの設定は再起動で消えて失格・減点の対象になりうる。このリストは「やった変更が再起動後も残るか」を確認するためのもの。

## 原則

- [ ] 変更はすべて「ファイル」か「初期化手順」に残す。その場のコマンド実行だけで済ませない
- [ ] 作業メモを残す（何を・なぜ・どこに変更したか）。終盤は記憶が曖昧になる

## アプリケーション

- [ ] コード変更はビルドして配置まで済んでいるか（ソースだけ直してバイナリが古い、がないか）
- [ ] 起動は systemd 等の仕組みに乗っているか（手で叩いたプロセスは再起動で消える）
- [ ] 環境変数や設定ファイルの変更は、サービス定義側に反映したか

## ミドルウェア

- [ ] nginx の変更は設定ファイルに書いたか（`nginx -t` 通過済みか）
- [ ] MySQL の `SET GLOBAL` で変えた値は my.cnf にも書いたか
- [ ] 追加したインデックスは初期化 SQL / マイグレーションに含めたか（DB を初期化し直しても効くか）

## データ・ファイル

- [ ] アプリが参照する静的ファイルや生成物は、再起動・再配置後も同じ場所にあるか
- [ ] ログのローテーションや出力先変更で、計測（isucon-kit の収集）が壊れていないか

## 最終確認

- [ ] 可能なら一度サービス（またはマシン）を再起動して、ベンチが通ることを確認する
- [ ] 再起動後のスコアが再起動前と大きく乖離していないことを確認する
- [ ] 当日のレギュレーションとマニュアルの記述が最優先（このリストと食い違えばマニュアルに従う）
